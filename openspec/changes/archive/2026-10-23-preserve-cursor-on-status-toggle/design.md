## Context

См. proposal.md — Why. Сейчас `toggleStatus` в `main.ts` строит транзакцию без поля `selection`/`selections`; замена занимает всю строку (`ch: 0 … text.length`), и редактор размещает курсор по правилам маппинга CodeMirror — фактический скачок в конец вставки. При этом команда Alt-Enter (`toggleTask`) уже решает ту же проблему явно: читает курсор до транзакции и передаёт `selection` в транзакцию. Длина строки при переключении статуса сохраняется (`lib/tasks.ts`, `setStatus` меняет ровно один символ), поэтому запомненные координаты остаются валидными. API Obsidian поддерживает нужное поле: `EditorTransaction.selections?: EditorRangeOrCaret[]` и `editor.listSelections(): EditorSelection[]` (проверено в `obsidian/obsidian.d.ts`).

## Goals / Non-Goals

**Goals:**
- Курсор и всё выделение (все курсоры, anchor/head) остаются в той же позиции документа после команды статуса.
- Восстановление позиции внутри той же транзакции — поведение Undo не меняется.

**Non-Goals:**
- Мультивыделение как способ применения команды: команда по-прежнему переключает статус только на строке последнего активного курсора.
- Изменение логики `lib/tasks.ts`, правила ±6 символов для Alt-Enter, подсветки, хоткеев.

## Decisions

- **Decision 1: явное восстановление `selections` в той же транзакции, а не вторым шагом.** До транзакции читается `editor.listSelections()`, массив передаётся в `editor.transaction({ changes, selections })`. Альтернатива «transaction, затем `editor.setSelections(...)`» отклонена: второй вызов — отдельный шаг для undo/redo и расширяем окно, в котором курсор виден «прыгнувшим».
- **Decision 2: замена всей строки сохраняется (не переходим на замену одного символа статуса).** Альтернатива — транзакция `{ from: {line, 2}, to: {line, 3} }` — спасает курсор маппингом CodeMirror, но позиции внутри `[ ]` (ch 2–3) всё равно сдвигаются на 1 символ, и результат зависит от `assoc` маппинга. Явная передача selections даёт точное соответствие требованию («символ за символом») независимо от правил маппинга.
- **Decision 3: маппинг `EditorSelection` → `EditorRangeOrCaret`: caret как `{ from: pos }` (без `to`), выделение как `{ from: anchor, to: head }`.** Для обычного одиночного курсора (anchor == head) это caret в исходной позиции.
- **Decision 4: ранний выход для не-задачи сохраняется.** Если `newLine === text`, транзакция не создаётся — нет ни изменения, ни движения курсора.

## Risks / Trade-offs

- [Транзакция принимает `EditorRangeOrCaret`, который не различает направление выделения (anchor/head)] → Для caret-выделений (обычный случай команды) направление не существует; для выделенного диапазона восстанавливается сам диапазон. Сдвиги направления в редком сценарии «реверснутая строка» не влияет на положение курсора и отмечен как известный компромисс.
- [Пользователь нажимает команду ядром Obsidian, а не хоткеем палитры — путь тот же] → Оба пути вызывают один `editorCallback`, поведение не расходится.

## Migration Plan

Без миграции: сборка (`npm run build`) и перезагрузка плагина. Роллбэк — возврат к транзакции без поля `selections`.

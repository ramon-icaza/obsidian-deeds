## Context

Подсветка статусов уже реализована декорациями уровня line (ViewPlugin в `main.ts` вешает классы `.deeds-status-done` / `.deeds-status-cancelled` / `.deeds-status-partial` на элемент строки), а итоговые цвета как значений четвёртого требования зашиты в `styles.css` и продублированы в README (таблица статусов). Мотивация — см. proposal.md («Why»). Затрагивается только фиксация нового значения цвета: классы, разбор задач, команды и зачёркивание не меняются.

## Goals / Non-Goals

- Goals: задать цвета «выполнена» = `#157a10` и «отменена» = `#870909` в `styles.css`; синхронно обновить hex-коды в README.
- Non-Goals: изменение цвета «частично выполнена» (`#ad9c00`), изменение зачёркивания, введение цветовых переменных/настроек плагина, изменение TS-кода и тестов, подсветка Reading mode.

## Decisions

- **Decision 1: цвета меняются прямо в `styles.css`, без вынесения в CSS-переменные.** Следуем текущей структуре проекта (design decision 4 исходного change): значения цветов в правилах классов, пользователи переопределяют через CSS snippet/тему. Введение переменных (`--deeds-done-color` и т. п.) — полезное будущее усовершенствование, но избыточное для такого компактного change и изменило бы больше поверхности, чем нужно. Альтернатива: CSS-переменные — отложить отдельным change.
- **Decision 2: одиночный источник цветов — `styles.css`, README — документация, обновляемая синхронно.** Спека задаёт hex-коды как контракт подсветки; чтобы документация и реализация не разошлись, задачу обновления README фиксируем явно в tasks.md.

## Risks / Trade-offs

- [Тёмные оттенки могут хуже контрастировать на тёмных темах Obsidian] → Новый выбор сделан пользователем по его хранилищу/теме; подсветка остаётся переопределяемой через CSS snippet, как и раньше (design decision 4 исходного change).
- [Расхождение hex-кодов между `styles.css`, README и спекой при будущих правках] → Три упоминания вносим одним change и явно проверяем задачей в tasks.md; при архивации дельта синхронизирует спеку.

## Migration Plan

Без миграции: пересборка (`npm run build`), перезагрузка плагина/хранилища обновляет стили. Роллбэк — возврат прежних hex-значений в `styles.css`.

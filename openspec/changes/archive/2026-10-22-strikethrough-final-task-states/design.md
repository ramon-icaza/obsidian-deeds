## Context

Зачёркивание — чисто визуальное поведение. Подсветка статусов уже реализована декорациями уровня line (ViewPlugin в `main.ts` вешает классы `.deeds-status-done` / `.deeds-status-cancelled` / `.deeds-status-partial` на элемент строки), поэтому «представление» уже изолировано в `styles.css`. Граница логики: `text-decoration` не влияет на разбор задач и не является частью требований «Подсветка статусов в редакторе» → см. дельту спеки в этом change.

## Goals / Non-Goals

- Goals: CSS-правила зачёркивания для двух классов строк; обновление README.
- Non-Goals: приглушение цвета, ссылочно-зачёркнутый префикс отдельной text-декорацией, подсветка/зачёркивание в Reading mode, изменение логики в `lib/tasks.ts`.

## Decisions

- **Decision 1: зачёркивание через класс line-декорации в CSS, а не text-декорацию в CodeMirror.** `text-decoration: line-through` на элементе строки проникает во весь inline-контент, включая префикс `- [✔] `, что даёт требование «вся строка зачёркнута» одним свойством. Альтернатива — text-декорация на диапазон текста (accept/reject через `Decoration.mark`) — избыточна: потребует трогать `main.ts` и дублировать логику, уже покрытую line-классами.
- **Decision 2: цвет сохраняем без приглушения.** Цвет — единственный визуальный различитель между «выполнена» и «отменена» после введения зачёркивания; обе категории визуально «закрыты» одинаковой механикой, различаются исходом по цвету. Альтернативу (desaturate) отложили как отдельную будущую идею.
- **Decision 3: строки без зачёркивания — «не начата» и «частично выполнена» — не трогаются.** Требование явно называет только финальные исходы; `deeds-status-partial` остаётся цветом без `text-decoration`.

## Risks / Trade-offs

- [Тема пользователя может перекрыть `text-decoration` или color своих CSS-правил] → Подсветка уже документирована как override-able через CSS snippet (design decision 4 из исходного change); поведение не ломается, стиль просто переопределяется.
- [`text-decoration` на чтении модов, отличных от Live Preview/source] → line-декорации применяются только в редакторе (CM6), Reading mode остаётся без изменений, как и раньше.

## Migration Plan

Без миграции: сборка (`npm run build`) и обновление кэша стилей при перезагрузке плагина/хранилища. Роллбэк — удаление добавленных CSS-свойств.

# Design: create-deeds-plugin

## Context

Плагин создаётся с нуля в пустом репозитории (см. proposal.md — Why). Ограничения среды: Obsidian Plugin API, редактор на CodeMirror 6, требования спеки — `specs/task-tracking/spec.md`.

## Goals / Non-Goals

**Goals:**
- Чистая, тестируемая без Obsidian логика распознавания и трансформации строк задач.
- Undo-совместимые правки и предсказуемая позиция курсора.
- Хоткеи, переназначаемые средствами Obsidian; работоспособность на мобильных через палитру команд.

**Non-Goals:**
- Подсветка в режиме чтения.
- Поддержка отступов, `- [x]`, мультикstrоочного выбора.
- Управление нумерацией (`1.` `2.` в примере набирается вручную).

## Decisions

1. **Команды через `addCommand` + дефолтные hotkeys, а не keymap CodeMirror.**
   Альтернатива (`registerEditorExtension` с keymap) жёстко зашивает клавиши: нет remap в настройках Obsidian, нет палитры, нет мобильных. Команды дают и палитру, и remap бесплатно. Rationale: требование «Доступность команд в палитре».

2. **Ядро — чистые функции над текстом строки.**
   `parseTask(line) → {status} | null` на regex `/^- \[( |✔|✘|✲)\] /` и `toggleStatus(line, target) → line` живут в отдельном модуле без импортов `obsidian`. Альтернатива — логика внутри команд напрямую. Rationale: четыре команды и подсветка разделяют одну логику; unit-тесты на node:test без поднятия Obsidian.

3. **Правки — одной транзакцией редактора** (`editor.transaction` / `EditorChange`), с подстройкой `selection` в той же транзакции. Альтернатива — замена строки через `setLine` с ручным восстановлением курсора. Rationale: атомарность и штатный undo (требование «Отмена операций через Undo»); все маркеры односимвольные, длина строки при смене статуса не меняется, курсор не двигается вовсе.

4. **Подсветка — `registerEditorExtension` + ViewPlugin + `Decoration.line` с классом, цвета в `styles.css`.**
   Альтернативы: inline-стиль (CM6 `Decoration.line` поддерживает только `class`, не style); Decoration.mark на маркер (отклонено — по решению красится вся строка). Классы `.deeds-status-done/-cancelled/-partial { color: ... }`. Rationale: разрешает пользователю переопределять цвета своей темой/CSS-сниппетом.

5. **Обход строк — только видимая область** (`view.visibleRanges`) в декорациях. Альтернатива — весь документ. Rationale: O(видимое) вместо O(документ), декорации пересчитываются штатно при изменениях.

6. **Каркас — официальный шаблон Obsidian sample plugin**: `manifest.json`, esbuild + TypeScript, `main.js` в корне. Репозиторий пуст, альтернативы не рассматриваются.

## Risks / Trade-offs

- [Нативный чекбокс: клик/Ctrl+L создаёт `- [x]`, строка выпадает из всех функций] → Принято решение игнорировать (см. proposal). Задокументировать в README плагина: статусы менять только хоткеями плагина.
- [Alt-клавиши могут конфликтовать с хоткеями ОС или других плагинов] → Команды remap-ятся в настройках Obsidian; конфликт не ломает функциональность.
- [Неизвестно, как Obsidian рендерит `[✔]/[✘]/[✲]` в Live Preview (возможен штатный чекбокс-виджет поверх нашей подсветки)] → Не влияет на корректность (подсветка наша, текст остаётся в строке); выяснить при имплементации, при необходимости поправить CSS-специфичность.
- [Пользовательский CSS-сниппет может перебить наши цвета] → Осознанный trade-off решения 4; специфичность классов подберётся при имплементации.
